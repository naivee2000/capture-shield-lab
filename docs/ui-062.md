# Version 0.6.2 UI refinement

This release changes presentation, not the audio capture backend, capture-stop lifecycle, recognition engines, global shortcuts, or the Legacy sharing flag. The blue/purple system/meeting indicator investigation is deferred at the operator's request. No new receiver-invisibility verdict is claimed.

## Behavior

- Normal paints an opaque dark backdrop. Legacy paints the same backdrop at 80% alpha. Window alpha is 1 in both modes; text, replies, code, images and native controls are not faded as a group. Images keep their intrinsic transparency. Shared appearance code applies to main/popup windows and owned sheets; system-provided control materials can keep their own opaque fills.
- The speech panel is 36 logical points at rest and during recording/processing, with no empty result box. Recording shows source, timer and Stop. Source/language/preparation, details and retained-text editing are mutually exclusive disclosures. Closing/folding preserves pending text. Explicit Cancel/Discard keeps its existing destructive-to-that-recording meaning.
- Completed retained text can be edited and explicitly added, with existing draft insertion guards and exactly-once handling. Successful safe automatic append remains the default. Partial recognition stays read-only.
- A retained editor grows to at most 120 points or 25% of available content height. Chat composer text grows within a viewport-dependent 56–160 CSS-pixel cap; attachment controls are outside the text cap. Recognized image thumbnails use 56–64 CSS pixels, retaining their preview/remove controls. Paste/review actions share the Images toolbar menu so the minimum window really fits. No global font/page-zoom reduction is applied.
- Compatibility moves to a compact toolbar icon. Page notices are dismissible and only reserve space when relevant; details remain available without repeating speech status in a second row.

## WebKit appearance compatibility

`NSWindow.alphaValue = 0.8` cannot keep foreground text opaque. `underPageBackgroundColor` plus transparent HTML/CSS alone was tested on this host and still produced an opaque WebKit document base.

`WebBackgroundCompatibility` therefore isolates WebKit's **non-public** `_setDrawsBackground:` / `_drawsBackground` appearance property, accessed through guarded KVC. It changes this app's rendering only; it neither bypasses screen capture permission nor suppresses a system privacy indicator. The implementation checks both selectors before use. When unavailable it keeps readable, full-alpha content, reports the limitation in Compatibility and displays a Legacy notice instead of reverting to faded text. Availability is not a guarantee of behavior on future WebKit releases.

An isolated-world bridge passes only a Boolean indicating that a supported chat layout is present. Authentication and unknown pages restore normal WebKit background drawing. Native background and scoped page-surface styling are separate; no whole-page CSS opacity, private capture API, chat-content logging, or additional screen capture is involved.

References: [Apple underPageBackgroundColor](https://developer.apple.com/documentation/webkit/wkwebview/underpagebackgroundcolor), [WebKit macOS appearance implementation](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/mac/WKWebViewMac.mm).

## Reproduce checks

```bash
bash scripts/test.sh
CAPTURESHIELD_UI_EXPORT_DIR=/tmp/captureshield-ui-review bash scripts/test.sh --filter UIVisualTests
bash scripts/build.sh
bash scripts/doctor.sh
```

The optional export test creates native/WebView composite renders of a disposable **synthetic** page at 980×700 and 640×480, not desktop or meeting captures. Files stay outside Git. It covers idle, multiline, attachment, recording, processing, retained, cancelled and error presentations. The lifecycle states in these render fixtures are simulated; audio backend behavior is unchanged.
