# Floating focus review — 0.6.5 / build 14

Implementation is in progress. No receiver or background-appearance success is claimed by this document until device evidence is recorded.

## Behavior

Always on Top defaults on in Normal and Legacy, is saved independently, and follows Spaces and eligible full-screen application spaces. Turning it off restores normal stacking. Clicking another application does not close the panel. Command-Shift-M reveals the panel for typing and hides it again; a deliberate switch to another application is not undone when hiding.

Chat windows use a fixed public nonactivating NSPanel style. Pinning changes level and collection behavior, not the creation-time activation style. Normal sharing recovery retains the same panel type, WebView, data store, undo manager and frame. App-owned chat panels are excluded from candidate-panel original-sharing restoration. Private Cursor remains preview-only and requires the owned key window.

## Evidence ledger

- Local application build/sign/register passed in an isolated APFS workspace. The existing QA042 app was not replaced.
- Twenty script checks and seven native window cases passed. The synthetic background helper compiled for macOS 15.6.
- The first full native run was incomplete despite process exit 0; the completion guard rejected it. A SpeechTests-only run reproduced the exit before its final configuration test entered. That configuration test passes alone. An opt-in exit trace identified SwiftPM's async-main drain path; a debugger launch was denied by the system, and no permissions were changed. Early audio configuration, explicit AppKit launch, host activation and cancelling pending fixture focus did not repair the shared-host failure. These are failed diagnostic attempts, not accepted workarounds.
- Explicit fresh-host scheduling completed all 106 native cases (98 other, 7 window lifecycle, 1 system configuration), with the same two optional skips and every completion marker checked. The original shared-host failure remains recorded; no production audio code was changed.
- Actual packaged UI, cross-system acceptance, Chrome's physical inactive appearance, physical Pinyin and Teams receiver visibility are pending.

## Repeat and accept

Use the existing UI workflow with nine mandatory cases, three sequential rounds, ten minutes per round and no failure retries. A separate synthetic FocusHost is built only for tests, receives no personal data and is cleaned with the run. Native metadata records key/activation state but cannot prove pixel appearance. New scenarios must check input destination, focus return, pin on/off and a real full-screen background window. XCTest must not make the app active and then call that a successful nonactivation test.

Run the macOS 15/26/27 matrix and record actual OS/build, toolchain, commit and counts. Preserve full native failures separately even when UI tests can run. Use harmless Chrome content on the development Mac and an independent Teams receiver for appearance checks; no account data, audio or original captures enter Git.
